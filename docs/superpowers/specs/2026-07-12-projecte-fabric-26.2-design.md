# ProjectE / 等价交换 Fabric 26.2 完整移植设计

日期：2026-07-12  
状态：规格已批准；基础阶段已验证  
目标工程：ProjectE-Fabric-26.2

## 1. 目标

将 ProjectE（等价交换重制版）完整移植到 Minecraft Java Edition 26.2 的 Fabric 平台，不以删减功能、物品占位、空实现或仅能启动作为完成标准。

最终版本必须：

1. 保留 ProjectE 1.21.1 NeoForge 本体的全部可见内容、核心机制、配置能力、数据包接口、服务端行为和多人同步语义。
2. 调查用户提供的其他等价交换实现，吸收其中不与 ProjectE 核心冲突、且确实属于等价交换玩法的新增功能。
3. 在 Fabric 26.2 上使用原生、可维护的实现，不把 NeoForge API 通过脆弱的兼容桩硬塞进 Fabric。
4. 提供可逐项审计的功能矩阵和自动化验证，使“功能未阉割”能够由证据证明。

## 3. 完整性定义

“完整移植”至少包含以下类别，任何类别都不能以占位实现验收。

### 3.1 注册内容

- 全部物品和方块物品。
- 全部方块、墙体/落地变体和特殊爆炸方块。
- 全部方块实体、菜单、实体、声音、伤害类型、数据组件、配方序列化器和创造模式标签页。
- 全部翻译、纹理、模型、方块状态、声音定义和粒子/渲染资源。

必须涵盖但不限于：

- 贤者之石与修复护符。
- 三种共价粉。
- 16 色炼金袋与炼金箱。
- 六级卡莱恩之星。
- 炼金煤炭、莫比乌斯燃料、永恒燃料及其方块。
- 暗物质与红物质材料、方块、全套工具、剪刀、锤和熔炉。
- 暗物质、红物质与宝石盔甲及其全部能力。
- 转化桌、便携转化桌和知识宝典。
- 三等级能量收集器、三等级反物质中继器、两等级能量凝聚器。
- 暗物质台座和全部可放置/激活的台座物品。
- 戒指、护符、炼金石、催化器、透镜、占卜棒和爆炸物。

### 3.2 EMC 系统

- 显式 EMC 值加载。
- 配方递归推导、循环检测、最小成本选择和黑名单。
- 标签、剩余物、损耗/容器物品和多输出配方处理。
- 数据包重载后重新计算并同步。
- 物品组件/NBT 等价性策略。
- EMC 上限、溢出和无效值保护。
- 玩家个人 EMC 存储、学习、遗忘和知识宝典行为。
- 管理命令、查询命令和重载行为。

ProjectE 1.21.1 的 long 语义必须兼容。若引入 Fabricated Exchange 的任意精度 EMC，只能作为向上兼容的内部表示或可选扩展，不得破坏 ProjectE 的数值、网络和存档兼容语义。

### 3.3 机器与容器

- 收集器：光照/时间生产、燃料升级、相邻传输和 GUI 状态。
- 中继器：物品燃烧、EMC 缓冲、卡莱恩之星充能和相邻传输。
- 凝聚器：目标物品、输入消耗、输出堆叠、锁定和自动化。
- 炼金箱/袋：跨界面一致性、颜色隔离、存档和并发访问。
- 暗/红物质熔炉：速度、产量、燃料、自动输入输出和经验。
- 转化桌/平板：学习、搜索、分页、锁定、燃料槽、批量取出和 EMC 同步。
- 永恒密度宝石和水银之眼等特殊菜单。

### 3.4 工具、装备与能力

- 充能等级、模式切换和按键绑定。
- 范围采掘、范围耕作、剪切、砍伐和锤击。
- 世界方块转化和实体转化。
- 投射物、范围伤害、爆炸与安全规则。
- 飞行、移动、步高、抗性、饥饿/生命恢复和宝石装备套装能力。
- 戒指、护符和炼金石的主动/被动模式。
- 台座上的不同激活效果。
- EMC 消耗顺序：玩家存储、卡莱恩之星及其他合法来源，顺序与 ProjectE 一致。

### 3.5 数据与内容资源

冻结基线当前至少包含：

- 156 个生成配方文件。
- 173 个生成进度文件。
- 21 个生成战利品表。
- 30 组生成标签文件。
- 4 个世界转化数据文件。
- 2 个自定义转化数据文件。
- 170 个纹理资源和 15 个声音资源。

这些数量仅用作初始防回归快照。最终验收比较的是标识符集合和语义，不允许通过生成无效空文件来满足数量。

### 3.6 配置、命令和公开接口

- 客户端、通用和服务端配置全部提供 Fabric 等价实现。
- 配置项名称、默认值和范围尽量保持兼容；无法原样保持时提供迁移映射。
- /projecte 命令树、权限要求、错误信息和数据重载行为完整保留。
- 保留公开 EMC API、知识 API、归一化堆栈、转换代理和事件扩展点的 Fabric 等价接口。
- 提供稳定 API source set 或独立 API artifact，避免附属模组依赖内部实现。

### 3.7 第三方兼容

必须设计并验证：

- EMI：配方展示与 EMC 信息。
- REI：若 26.2 有稳定版本，则提供等价支持。
- Jade/WTHIT：机器 EMC、目标物品和工作状态显示。
- Trinkets：承接 Curios 饰品槽语义；缺少稳定 26.2 版本时，核心物品仍可从背包生效，兼容模块延后但不得删除相关能力。
- Fabric Transfer API：机器物品/流体/能量式存储交互中适用的自动化接口。
- 数据包、KubeJS/CraftTweaker 类集成：优先提供数据驱动 API；仅在目标依赖存在 26.2 Fabric 版本时启用直接兼容模块。

可选依赖不得成为模组启动的硬依赖，也不得在缺失时导致类加载崩溃。

## 4. 技术架构

### 4.1 工程与工具链

- Minecraft 26.2。
- Java 25；Gradle JVM、编译工具链与运行测试均使用 Java 25。
- Fabric Loom 1.17。
- Gradle 9.5.1。
- Fabric Loader 使用实现时最新稳定版本，最低基线 0.19.3。
- Fabric API 当前锁定 0.154.2+26.2；实施期间仅在验证通过后升级。
- Mojang 官方映射；对外 API 避免暴露不稳定的内部类。

版本号必须集中在 gradle.properties 或 version catalog，不散落在构建脚本中。

### 4.2 源码边界

单一 Fabric 工程按职责分包：

- api：稳定公开接口和数据模型。
- core：与加载器无关的 EMC、知识、归一化堆栈、转换和算法。
- content：物品、方块、方块实体、菜单、实体和玩法实现。
- platform.fabric：注册、生命周期、事件、网络、数据附件和传输 API 适配。
- client：屏幕、渲染、键位、提示和客户端缓存。
- compat：每个第三方模组一个隔离模块/包。
- datagen：配方、进度、战利品、标签、模型和语言数据生成。
- test：纯 Java 单元测试、Fabric GameTest 和快照验收。

核心算法不得直接引用 NeoForge 类。NeoForge 的 DeferredRegister、Capability、Attachment、EventBus 和网络类必须在 Fabric 层被替换，而不是复制空壳类型。

### 4.3 平台映射

| NeoForge 概念 | Fabric 26.2 方案 |
| --- | --- |
| DeferredRegister / RegistryObject | 原版 Registry + 集中式注册类 |
| Capability / Item handler | Fabric Transfer API 或明确的内部接口 |
| Player attachments | Fabric Data Attachment API 或持久组件封装 |
| Data components | 原版 DataComponentType 注册 |
| SimpleChannel / payload | Fabric Networking Payload API |
| MenuType / Screen | 原版 MenuType + Fabric ScreenHandler/Screen 注册 |
| Tick/EventBus | Fabric 生命周期、玩家、世界和交互事件 |
| Curios | 隔离的 Trinkets 兼容层 |
| NeoForge config | JSON5/TOML 兼容配置层，带服务端同步 |
| Datagen providers | Fabric Data Generation API |

若 Fabric API 没有语义等价的事件，应使用最小范围 Mixin，并为每个 Mixin 写明原因、目标方法和回归测试。

## 5. 数据流与权威性

### 5.1 EMC 重载

1. 服务端加载数据包中的 EMC、转换和黑名单数据。
2. 收集全部合法配方并构建依赖图。
3. 检测循环和不可解节点，计算稳定最小 EMC。
4. 原子替换当前映射；失败时保留上一份有效映射并输出完整诊断。
5. 向在线玩家同步版本号和必要差异。
6. 客户端只用于显示，不自行决定权威 EMC。

### 5.2 转化桌交易

1. 客户端发送意图：插入、学习、搜索或提取。
2. 服务端验证菜单、物品、知识、EMC 余额、数量和速率限制。
3. 服务端以单次事务修改输入、余额和输出。
4. 成功后同步菜单状态和玩家 EMC；失败时返回明确原因并保持原状态。

客户端提交的 EMC 值、物品数量或学习状态一律不可信。

### 5.3 机器自动化

机器每次工作先在服务端计算计划，再以原子步骤提交物品与 EMC 变化。模拟插入/提取必须无副作用，避免管道探测导致复制或吞物。

## 6. 存档与迁移

- 所有玩家数据、方块实体数据和物品组件使用带版本号的 Codec。
- 保留 ProjectE 标识符 projecte:*，降低命令、数据包和附属兼容成本。
- 为字段重命名、数值扩展和旧格式提供显式迁移器。
- 未识别字段尽量保留；无法迁移时输出坐标、玩家和字段路径，不静默清空。
- 单人、局域网和专用服务器使用同一服务端数据路径。
- 在发布前用真实测试世界验证关闭、重启、崩溃恢复和数据包重载。

不承诺直接加载 NeoForge 世界中的加载器专有附件；但必须提供可执行的转换工具或导入路径，覆盖玩家 EMC/知识、机器库存和关键物品数据。

## 7. 错误处理与安全

- EMC 运算使用检查加法/乘法，禁止静默溢出。
- 损坏或无效数据包条目提供资源 ID 和原因。
- 网络包验证方向、玩家状态、菜单类型、负数、上限和权限。
- 范围破坏、爆炸和世界转化尊重游戏规则、保护事件和不可破坏方块。
- 批量操作设置每 tick 预算，防止专服卡死。
- 可选兼容通过入口点和模组存在检查隔离，禁止仅引用缺失类就崩溃。
- 资源重载和存档写入采用先验证后替换策略。

## 8. 测试与验收

### 8.1 自动化测试

- EMC 算法：基础配方、多输出、剩余物、循环、黑名单、标签和溢出。
- 知识与余额：学习、遗忘、宝典、死亡、维度切换、重连和并发提取。
- 注册表快照：基线 ID 集合与 Fabric 构建 ID 集合逐项比较。
- 数据快照：配方、进度、战利品、标签和世界转化语义比较。
- Codec：全部持久化数据往返和版本迁移。
- GameTest：机器生产/传输、工具范围、饰品能力、台座和世界转化。
- 网络：非法数量、过期菜单、重复包和客户端伪造。

### 8.2 运行验收

- gradlew build 成功。
- 数据生成重复执行后工作树无差异。
- Fabric 客户端可启动并进入世界。
- 无客户端类的专用服务器可启动、建档、保存、重启。
- 两名以上玩家同时操作转化桌和机器无复制、吞物或串数据。
- 每个注册物至少完成获取、显示、主要交互和存档往返测试。
- 关键玩法按从贤者之石到宝石装备/终局机器的生存流程完整走通。

### 8.3 完整性门禁

维护 docs/porting/feature-matrix.md，每一项记录：

- 上游 ID/类/数据文件。
- Fabric 对应实现。
- 状态：未开始、实现中、已实现、已验证。
- 自动测试或人工验证证据。
- 差异及原因。

只有所有基线条目均为“已验证”，且没有未解释差异，才能宣称完整移植完成。

## 9. 实施顺序

1. 创建 26.2 Fabric 工程、许可证、构建和 CI。
2. 生成上游注册表/资源/行为功能矩阵。
3. 移植公开 API、归一化堆栈和 EMC 核心。
4. 移植玩家 EMC、知识、配置、命令和网络。
5. 移植基础材料、贤者之石、转化桌/平板。
6. 移植机器、容器和自动化接口。
7. 移植全部工具、盔甲、戒指、护符、投射物和台座能力。
8. 移植数据生成、资源、声音、进度和战利品。
9. 实现 EMI/Jade/WTHIT/Trinkets 等兼容层。
10. 评估并加入其他实现的非冲突新增功能。
11. 完成专服、多人、存档迁移和完整玩法验收。

每个阶段必须先建立能失败的测试/矩阵检查，再实现功能；不得把未实现行为用 TODO、空方法或永远返回默认值隐藏起来。

## 10. 许可证与归属

- 保留 ProjectE MIT 许可证、版权声明和必要作者归属。
- 对每个补充来源记录许可证和实际复用范围。
- 未明确许可的代码、纹理、声音或文案只用于行为研究，不直接复制。
- 发布包内包含许可证、NOTICE/credits 和来源说明。

## 11. 明确不接受的降级

- 只实现 EMC 和转化桌的“轻量版”。
- 删除冷门戒指、护符、台座或工具能力。
- 用静态 EMC 表替代配方推导。
- 只支持单人、不支持专用服务器。
- GUI 能打开但按钮/搜索/分页/同步不完整。
- 物品存在但主动或被动能力为空。
- 以 Fabric 缺少某个 NeoForge API 为理由直接删除功能。
- 只通过编译或启动测试就声称移植完成。

## 12. 规格完成条件

本规格经用户复核后，下一步编写细粒度实施计划。实施计划必须把功能矩阵、测试和各模块移植拆成可独立验证的小步骤，同时维持本规格定义的完整范围。
